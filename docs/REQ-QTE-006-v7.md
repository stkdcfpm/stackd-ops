D7 confirmed and D6 answered by the operator (2026-11-28): **insurance is part of the freight charge** — this supersedes the earlier "cost-only insurance inside line prices" decision. **Type:** Feature (engine contract + customer document). One additive Supabase migration. Single phase; sizing: touches `cQteLine`, `cQte`, `qteSellTotals`, `saveQte`, `calcQte`, `rQLT`, `prevQteDoc`, `renderQteLineHistory`, `qteCustomerModel`, `qteCustWarnings`, `qteFormSnapshot`, `openQte`/`editQte`, four Cloud Data row builders (`refreshQteFromSupabase` mapping, `persistQteChange`, `migrateQteToSupabase` insert, `saveQte`'s `qtRow`) + migration `0011` — expect several gate rounds, as REQ-QTE-005 needed.
**Operator decisions (2026-11-28):** freight at cost (no markup); print the CBM estimate labelled "Freight (estimate)" with a tick; insurance travels with the freight charge (the whole shipment is insured as part of freight); DG surcharge travels with freight (D7); existing quotes stay Included; ships after the current container quote (interim workaround meanwhile). **Settled:** D6 and D7 — see §8.

## 1. Problem (verified against live code)
`cQteLine()` (`index.html:14980`) computes `landed = cost + freight + dgAmt + ins + duty` (`14999`): freight from the line's CBM and the Freight Mode (`14984-14990`), `ins = (cost + freight) × rate` (`14997`), `duty = cost × dutyPct` (`14998`), `dgAmt = QR.dgSurcharge` for a DG line (`14991`). A line's selling price is `landed × (1 + effective markup%)` (`qteSellTotals`, `15021`; `qteCustomerModel`, `16224`), so international freight, and the insurance charged on it, are **always inside every line's price and carry the line's markup**. The customer document has no freight row (`16232-16236`); the three overhead overrides never touch freight.

## 2. Treatment field
`Quote.freightTreatment`: **`'included'`** (default; today's behaviour), **`'separate'`**, **`'excluded'`**. Stored **only for `separate`/`excluded`**; for `included` the key is **omitted** (never stored as `'included'`, never `undefined`) — identical rule in the local record, the form, the Cloud column (`freight_treatment` is `null` for included) and every test. `Quote.freightAmount` (USD, number): present only for `separate` and only when the operator typed a value (a typed `0` is stored); blank = key omitted.

## 3. Engine contract (resolves gate findings 1-3)
**3.1 Signature.** `cQteLine(line, qr, freightMode, totalCBM, quoteInsRateRaw, freightTreatment)` — new 6th parameter; `undefined`/`'included'` = exactly today's arithmetic. **Callers:** `rfqLandedGBP` (`4263`, four arguments) is unchanged and stays on `included` — RFQ landed-cost ranking needs freight; `cQte` (`15036`) passes `qt.freightTreatment`; the three form-driven paths `rQLT` (`15428`), `calcQte` (`15529`) and `saveQte` (`15629`) read the new form field and pass it, so editor, saved record and document cannot disagree. A test enumerates every `cQteLine(` call site and fails if one is added without a decision.
**3.2 `separate` / `excluded` line arithmetic.** The shipment-side items — **freight, insurance and the DG surcharge — leave `landed` and belong to the freight figure** (operator decisions D6/D7). Landed = `cost + duty`. Per line the engine still computes `freight` (CBM-driven), `dgAmt` and `ins = (cost + freight) × insPct/100` **exactly as today** (same base, same per-line `Ins %` / quote-level `qf-insRate` cascade — insurance is no longer re-based, it simply moves out of the line price); these keys keep returning their values for display and history. For `separate` the **estimate** is `Σ (freight + dgAmt + ins)`, passed through at cost (no markup); a typed amount replaces the whole figure (a forwarder's all-in number is assumed to include insurance and DG). For `excluded` all three are dropped (the buyer arranges and insures the shipment): `freightLine = 0` and none of them is in any price. `.landed` is therefore ex-freight, ex-DG, ex-insurance for non-included treatments; new key `.freightTreatment` echoes the normalised treatment. `qteFreightTreatment(v)` normalises `undefined`, `''` and any unknown string to `'included'`; it is the only place the three values are interpreted. The per-line return keeps the existing keys (`.freight`, `.dgAmt`, `.ins`, `.insPct`, `.duty`, `.landed`).
**3.3 Totals.** `cQte()` returns two new fields: `freightEst = Σ (line.freight + line.dgAmt + line.ins)` and `freightLine` = `0` for `included`/`excluded`; for `separate`, the typed `freightAmount` if present else `freightEst`. `qteSellTotals(lines, lineCalcs, quoteMarkup, overheadTotal, fxGBPUSD, freightLine)` — the new argument is **6th**, default 0, so the three existing callers (`15040`, `15535`, `15652`) are unchanged (`included` passes 0). **`freightEst` is informational for `included` and `excluded` (never added to any total); only `freightLine` is added.** For `excluded` the engine still returns the per-line `freight`/`dgAmt`/`ins` values (shown on the internal sheet) and `freightEst` stays computed; only `landed` and `freightLine` change. Then: `totalLanded = Σ line landed` (ex-freight for non-included); `quotedTotal = totalLanded + freightLine + overhead`; **`sellUSD = Σ line sell + freightLine + overhead`** (freight is added **unmarked**, like overhead); `sellGBP = sellUSD / fx`. `calc_totalLanded` is **ex-freight/insurance/DG for non-included quotes** (its Sheets label "Grand Total" is unchanged and therefore reads lower for those quotes — documented in the user guide, no schema change); `saveQte` stores `calc_totalLanded`, `calc_sellUSD`, `calc_sellGBP` from these, so `qteCustomerModel.engineTotal` (`16238`) and the stored value agree and the drift acknowledgement (`16307`) does not fire falsely. REQ-QTE6 regression: every existing `cQte()` output is pinned for `included`; new fixtures pin `separate` and `excluded`.
**3.4 Worked example** (1 line, cost $10,000, CBM 20 at $100/CBM LCL → freight est $2,000, insurance 0.5%, duty 0, markup 20%, **no DG line**, no overhead; a DG line adds `QR.dgSurcharge` to `included` landed and to the `separate` freight figure, never to a line price):

| | Included | Separate (amount blank → estimate) | Separate (typed $1,800) | Excluded |
|---|---|---|---|---|
| `line.ins` (still returned) | (10,000+2,000)×0.5% = 60.00 | 60.00 (in freight) | 60.00 (unused) | 60.00 (unused) |
| landed | 12,060.00 | 10,000.00 | 10,000.00 | 10,000.00 |
| line sell (×1.20) | 14,472.00 | 12,000.00 | 12,000.00 | 12,000.00 |
| freightLine (freight + DG + insurance, unmarked) | 0 | 2,060.00 (est.) | 1,800.00 | 0 |
| **sellUSD / printed Total** | **14,472.00** | **14,060.00** | **13,800.00** | **12,000.00** |
| quotedTotal | 12,060.00 | 12,060.00 | 11,800.00 | 10,000.00 |

## 4. Requirements
- **REQ-QTE6-001 — Persistence.** As §2. Form: a select `qf-fr` placed with `qf-mode` (`3002-3012`) and a number input `qf-frAmt` shown only when `qf-fr = separate` (placeholder "Blank = estimate from CBM"). `qf-frAmt` validation (`vFormOk`): blank or a finite number `0 ≤ x ≤ 10,000,000`; a negative, non-numeric or larger value blocks Save with `vErr` (a negative would drop `sellUSD` while printing no row). Switching away from `separate` clears `qf-frAmt` visibly, so a stale figure can never resurrect. `openQte`/`editQte` reset/load both fields; `qteFormSnapshot()` (`16377-16385`, hard-coded id list) gains `qf-fr`, `qf-frAmt`; `saveQteSetup()` in `tests/run.js` resets both (module-level `mockElements` never clears).
- **REQ-QTE6-002 — Engine.** §3, including the pinned regression and the `cQteLine(` call-site test.
- **REQ-QTE6-003 — Customer document.** `qteCustomerModel()` adds a `freight` row **first** in `charges[]` (print order = array order, `16232`): label **"Freight"** when a typed amount exists, **"Freight (estimate)"** when the engine estimate is used. A zero amount (typed `0` or a zero estimate, e.g. all line CBM 0) prints **no row**, matching the existing `amount > 0` filter (`16236`). The header line "Shipping: <mode>" (`16273`) prints as today for `separate`/`included` and is **omitted for `excluded`**. Reconciliation rule unchanged: printed Total = Σ printed lines + Σ printed rows (`16237`); **the bound is `|printed Total − sellUSD| ≤ Σ over printed product lines (0.00005 × qty + 0.005) + 0.005 × 4` (origin, destination, admin and freight are each counted whether or not they print, because a sub-half-cent charge is filtered from the document by `amount > 0` after `qteRound2` yet still sits in `sellUSD`)** (REQ-QTE-005's bound plus one half-cent per row), asserted numerically in a test; AC restates it.
- **REQ-QTE6-004 — No leak.** Only the one freight amount prints. CBM, rates, container costs, markup %, insurance, `freightEst` vs typed delta and the treatment name never print; the REQ-QTE5 sentinel test is extended with sentinels for CBM, `lclPerCBM`/container rates, markup %, insurance % and a typed-vs-estimate delta.
- **REQ-QTE6-005 — Pre-send warnings.** New `qteCustWarnings` entry **`{k:'frest', lvl:'ack'}`** ("Freight is an estimate from CBM rates — the forwarder's figure may differ") when `separate`, no typed amount, `Σ line.freight` rounded to cents is `> 0` and **`qteRound2(estimate) ≥ 0.01`** (the printed row threshold); `qteCustGenerate` re-enforces it like the other acks (test via `testAsync`). The estimate is recomputed live from current `QR` rates, so a reprint after a Settings change can print a different amount; the existing drift acknowledgement (`16307`) also catches it because `calc_sellUSD` now includes freight. Best-effort text warning dropped as untestable. **Zero-freight guard (gate findings r1-2, r3-1):** because insurance is `(cost + freight) × rate`, the estimate is positive even with no CBM, so the guard keys on **`Σ line.freight` (the CBM-driven freight alone) rounded to cents `= 0`**, not on the whole estimate: for `separate` with no typed amount and `Σ line.freight = 0`, or with a typed `0`, add **`{k:'frzero', lvl:'ack'}`** — "No freight is calculated (no CBM or rate): the Freight row would show insurance only, or no row at all for a typed 0. Check before sending" — so a missing CBM can never silently under-quote. In that case `frest` is not also raised (one ack, `frzero`). A line with CBM 0 among LCL lines already shows as a zero Freight cell on the internal sheet; the estimate row on the editor footer (REQ-QTE6-007) lists the number of lines with CBM 0. For `excluded`, a **warn** (not ack) says "Freight is not included — make sure your price basis says so".
- **REQ-QTE6-006 — Versioning (resolves finding 4).** `history.push` entries gain `ft` (`'included'|'separate'|'excluded'`); the change detector (`15642`) also compares `(lastV.ft||'included') !== currentTreatment`, so switching treatment (which changes every line's `landed`/`ins`/`sellPrice`) creates a new version. The comparison runs inside the existing per-line loop at `15642`, using the **normalised** value from `qteFreightTreatment()` (`''` and absent both mean `'included'`). A typed freight amount is quote-level, not per-line, and does not version lines.
- **REQ-QTE6-007 — Other surfaces (resolves finding 7).** `prevQteDoc` (internal sheet): per-line Freight column stays (shows the line's CBM-driven freight, `calc.freight`), Landed column header becomes **"Landed (cost + duty)"** when not `included`; the Freight and Insurance columns (internal sheet) and the Ins $ column (editor grid) get a treatment-specific header suffix (there is no DG-amount column in either surface; erratum 2026-11-28). The internal sheet's per-line Freight cell keeps showing `calc.freight` (the line's CBM-driven freight), not a per-line `freightEst`, which does not exist (erratum 2026-11-28): **`separate` with the estimate in use → " (in Freight row)"**; **`separate` with a typed amount → " (replaced by typed freight)"**; **`excluded` → " (not charged)"**; `included` → no suffix (headers unchanged). The row therefore always reads Cost + Duty = Landed; totals block gains a **Freight** row (`separate`) and prints the treatment; INTERNAL banner unchanged. `rQLT` live grid: same header and suffix rule, plus an editor footer line showing estimate vs typed amount. `renderQteLineHistory` appends the text **"Freight: shown separately"** or **"Freight: not included"** to each version row whose `ft` is not `included` (history rows keep storing `ins` and `landed` as computed; they are read together with `ft`) (nothing for `included`). The editor footer element (written by `calcQte()`) reads exactly **"Freight estimate $X (N lines with no CBM) — using typed $Y"** (the clause after the dash only when a typed amount exists), shown for `separate` and `excluded` only. Text by treatment: `separate`, no typed amount → "Freight estimate $X (N lines with no CBM)"; `separate`, typed amount → "Freight estimate $X (N lines with no CBM) — using typed $Y. Insurance % has no effect while a typed freight amount is used"; `excluded` → "Freight not included. Insurance % has no effect while freight is not included"; `included` → no footer. `qteToPoConvert` (`16126-16170`) reads `l.cost`, never `cQte`, so freight never reaches a Purchase Order — stated, with a test. The promotion queue has no `cQteLine` call (verified by the call-site test).
- **REQ-QTE6-007b — Insurance overrides under non-included treatments.** A per-line `Ins %` and the quote-level `qf-insRate` continue to feed `line.ins` and so the `separate` estimate; with a **typed freight amount** or `excluded` they have no price effect, and the `rQLT` footer says so, using exactly the per-treatment text specified in REQ-QTE6-007. - **REQ-QTE6-008 — Cloud Data & carry-forward.** Two nullable columns on `quotes`: `freight_treatment text`, `freight_amount numeric` (migration `0011_quotes_freight_treatment.sql`, additive; latest existing is `0010`). **Four row builders, each with its own test:** the refresh mapping (`6619`, `refreshQteFromSupabase`) with `if (row.x != null) obj.x = row.x` (never `!= null ? val : undefined`); **`persistQteChange()` (`6854`; row literal `6863`, the shared helper with 9 call sites that status changes and other updates go through)**; the `migrateQteToSupabase` insert (`7395`); `saveQte`'s `qtRow` (`15693`). ## 8. Operator decisions (settled 2026-11-28)
- **D6 — insurance:** the whole shipment is insured as part of the freight charge. So insurance rides in the Freight row for `separate` (estimate `freight + DG + insurance` at cost; a typed forwarder amount replaces it) and is absent for `excluded`. **Please confirm this reading:** the earlier answer "cost-only insurance inside line prices" is replaced, and the freight estimate keeps today's insurance basis, `(cost + freight) × rate`.

## 9. Risks
